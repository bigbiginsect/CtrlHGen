## Live incidents and fixes

1. The DSW instance no longer contained the Phase A `/tmp` pytest target.
   Pytest 8.3.5 was reinstalled only under `/tmp/ctrlhgen-phase-b-pytest`; the
   shared environment was not modified.
2. PyKEEN initially defaulted to `/root/.data/pykeen`. The first sampling
   preflight was stopped before it wrote raw cache files, and `PYKEEN_HOME` was
   fixed at `/mnt/workspace/cache/pykeen`. README now documents this persistent
   cache variable.
3. PyKEEN 1.11.0 does not expose `pykeen.__version__`, causing manifest
   publication to fail after the first KG pickle write. Commit `cbfc3c3` reads
   the installed distribution version through standard package metadata and
   adds a regression test. The incomplete pickle was moved, not deleted, to
   `failed-artifacts/` before sampling was rerun.
4. `/usr/bin/time` is absent from the DSW image. The SFT command itself had not
   started; the retry used shell timestamps and did not install a system package.
5. TRL interpreted the 204 merged prompts as 204 GRPO steps. Saving a roughly
   1.3 GB Trainer checkpoint every step without retention would exceed the
   196 GB volume. The run was stopped after 23 successful steps and its 30 GB
   checkpoint directory was preserved unchanged under
   `failed-artifacts/grpo-save-every-step-cbfc3c3`. Commit `92088e5` keeps the
   latest two step checkpoints, preserving resume capability while bounding
   disk use; a regression assertion covers the policy. The complete rerun used
   3.5 GB for live GRPO checkpoints and left 159 GB free.
6. CUDA emitted warnings that CuBLAS and memory-efficient attention operations
   were not bitwise deterministic despite seeded deterministic-warn mode.
   This does not block the end-to-end smoke, but exact GPU bitwise
   reproducibility is not claimed and should be addressed before Phase C.
